# Reed

Reed is a Paper 26.2 fork built with paperweight 2. Its current behavior is
implemented by Reed-owned Java sources, 17 feature patches, and two build-script
patches.

## Build baseline

| Component | Version |
|---|---|
| Minecraft / API | `26.2` |
| Paper commit | `b4e83001d95e1af79e01c9523f2206c10efe3663` |
| paperweight patcher | `2.0.0-beta.21` |
| Gradle wrapper | `9.4.1` |
| Java toolchain / release | `25` |

`gradle.properties` pins the Minecraft/API versions and Paper commit. The root
`build.gradle.kts` selects paperweight and Java; the wrapper selects Gradle.
The server's upstream-derived build script currently uses Mache
`26.2+build.1`.

## Repository layout

| Location | Purpose |
|---|---|
| `reed-api/src/main` | Reed-owned API entry point and debug block contracts |
| `reed-server/src/main` | API provider, configuration, and debug block service implementation |
| `reed-server/src/test` | Focused Reed regression tests |
| `reed-api/paper-patches` | Three patches extending existing Bukkit/Paper API types |
| `reed-server/paper-patches` | Five patches for branding, configuration reload, and CraftBukkit API implementations |
| `reed-server/minecraft-patches` | Nine patches for Minecraft, EAR, and Moonrise behavior |
| `reed-api/build.gradle.kts.patch`, `reed-server/build.gradle.kts.patch` | Patches for the upstream module build scripts |
| `build-data` | Access transformers and development imports |

The following locations are generated by applying patches:

- `paper-api`: patched upstream API sources and their Git patch history.
- `paper-server`: patched upstream Paper/CraftBukkit sources and their Git patch history.
- `reed-server/src/minecraft/java`: patched Minecraft and imported sources with
  their Git patch history.
- `reed-api/build.gradle.kts` and `reed-server/build.gradle.kts`: patched module
  build scripts.

Edit Reed-owned classes directly. For upstream classes, edit the appropriate
expanded source repository and rebuild its patches. Module build-script edits
must also be captured in the corresponding build-script patch. The upstream
checkout under `.gradle/caches/paperweight/upstreams/paper` is a build cache.

## Features

| Feature | Current behavior |
|---|---|
| Reed identity | Reed artifact names and `windmilltown:reed` branding; Reed also accepts the Paper brand in compatibility checks |
| Reed API entry point | `Reed.server()` loads `ReedServerImpl` through `ServiceLoader`; `ReedServer` currently exposes `debugBlocks()` |
| Global configuration | Typed Configurate configuration in the Paper settings directory, normally `config/reed.yml` |
| Always tick entities | Bypasses Entity Activation Range for entities already eligible to tick |
| Delayed falling-block source removal | Retains the source until the falling entity's first tick, before gravity and movement |
| Mojang entity collision | Runtime-selectable Mojang movement, candidate collection, axis collision, and step-height path |
| Trident auto despawn | Per-trident `isAutoDespawn()` / `setAutoDespawn(boolean)` with a global default and persistent custom data |
| Block placement updates | Per-player `getDoBlockPlacementUpdate()` / `setDoBlockPlacementUpdate(boolean)` controls updates during placement and deferred replay |
| Debug blocks | Jigsaw-backed settings and state, synchronous listeners, actual update sources when known, and tick context |
| Player no clip | `isNoClip()` / `setNoClip(boolean)` enables collision and piston bypass while flying; creative mode is not required |
| Entity ticking order | Optional stable ordering within each chunk during status transitions and entity persistence |

The Trident and Player methods extend the existing Bukkit interfaces. Debug block
APIs live under `net.windmilltown.reed.debugblock` and are reached through
`Reed.server().debugBlocks()`.

## Configuration

The current default values are:

```yaml
version: 1
gameplay:
  legacy-falling-block-entity-ticking: false
paper-fix:
  always-tick-entities: false
  use-vanilla-entity-collision: false
  use-vanilla-entity-ticking-order: false
features:
  trident-auto-despawn: true
  debug-blocks: false
```

All settings apply globally. Reed loads them after Paper's global/world-default
configuration and before worlds load. `/reload` replaces the active configuration
only after parsing, version checking, transformation, and saving succeed. A
failed reload logs an error and retains the previous configuration. Plugins do
not receive the internal configuration object through the Reed API.

## Build and patch maintenance

Run commands from the repository root. On Unix, use `./gradlew` in place of
`.\gradlew.bat`.

Apply all upstream and Reed patches:

```powershell
.\gradlew.bat applyAllPatches
```

Compile the API and server:

```powershell
.\gradlew.bat :reed-api:compileJava :reed-server:compileJava
```

Rebuild the patch layer you edited:

```powershell
.\gradlew.bat rebuildPaperPatches
.\gradlew.bat :reed-server:rebuildPaperServerPatches
.\gradlew.bat :reed-server:rebuildMinecraftPatches
```

`rebuildPaperPatches` captures API and upstream single-file build patches.
`:reed-server:rebuildAllServerPatches` rebuilds both server patch layers.
Feature changes must be committed in the relevant expanded source repository
before rebuilding; amend or fix up the existing feature commit when updating it.
Keep patch ordering and subjects stable.

Build the runnable Paperclip server jar:

```powershell
.\gradlew.bat :reed-server:createPaperclipJar
```

The local output is
`reed-server/build/libs/reed-paperclip-26.2.local-SNAPSHOT.jar`.

Run the focused Reed regression suite when relevant to a change:

```powershell
.\gradlew.bat :reed-server:test --tests net.windmilltown.reed.ReedTestSuite
```

The suite includes configuration/provider checks, API checks, collision samples,
and bytecode assertions for important injection and call-order behavior. It does
not establish full in-game redstone or physics equivalence. Prefer compilation
and targeted validation for routine changes; add tests only for critical behavior.

## Documentation and coding rules

Use concise type names and direct implementations. Avoid speculative defensive
branches and unnecessary abstraction. In Mojang classes, prefer fully qualified
names for new types used only a few times, and mark changes with identifiable
`// Reed - ...` or paired `// Reed start/end - ...` comments. Follow the surrounding
source style and preserve execution order.

Text files use UTF-8 without a BOM and LF line endings; Windows batch files use
CRLF. Keep this README synchronized when changing features, configuration,
patch inventories, or the build baseline.

Additional local reference documents are kept in the Git-ignored `docs/`
directory: the patch style guide, WTServer migration record, and inventories for
the API, Paper-server, and Minecraft patch layers. They are not included in a
fresh repository checkout.
